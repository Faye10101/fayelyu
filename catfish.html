Overview

A broken bar website, rebuilt from the ground up

The Catfish Bar is a fictional craft beer and live music venue in Fitzroy, Melbourne. The brief asked me to identify what was broken about an existing design and rebuild it — with real functionality, not just visuals.

I rebuilt the entire site with a vintage dark-green and amber aesthetic that felt true to the bar's character: handcrafted, warm, slightly rough around the edges. Playfair Display SC for the headings, cream text on deep green backgrounds, amber glow accents throughout.

What I Built

Seven pages, fully wired up

Every page serves a purpose. The product catalogue is live — you can search, filter by style, and add items to a cart that persists as you browse. The checkout flow validates your input and gives you a confirmation. Nothing is faked.

  • Real-time search & filtering — type a beer name or pick a style tag and the catalogue updates instantly, no page reload.
  • Persistent shopping cart — add items, navigate away, come back — the cart remembers. Quantity controls, running total, remove items.
  • Checkout & confirmation flow — form validation, an order summary, and a confirmation page that ties it all together.
  • Responsive layout — designed at 390px (iPhone) and 1440px (desktop), tested in between. No horizontal scrolling, no broken text.

The CSS is modular: separate files for layout, components, and each page. This made it much easier to debug — if a card looked wrong, I knew exactly which file to open.

Usability Testing

I tested it, found problems, then fixed them

After building the first version, I ran usability tests and identified four problems that real users kept running into:

Problem 1

The cart icon gave no feedback when an item was added — users didn't know if it worked.

Fix

Added a count badge on the cart icon and a brief "Added!" toast notification.

Problem 2

The search bar was hard to find — users expected it at the top of the product page.

Fix

Moved search to the top of the catalogue, above the filter tabs.

Problem 3

Filter tags and search results didn't combine — filtering cleared the search.

Fix

Rewrote the JS filter logic so both conditions apply simultaneously.

Problem 4

The checkout button was disabled until the form was complete, with no explanation why.

Fix

Added inline validation messages so users know which fields still need attention.

"Testing felt like cheating at first — I thought I knew my own site. Then someone couldn't find the search bar and I realised I'd been looking at it too long."

Reflection

What I learned

This was the first project where I was fully responsible for both the design and the code. The most valuable thing wasn't any particular technique — it was learning to treat design decisions as hypotheses, not conclusions. Every layout choice I made before testing turned out to have at least one thing I'd gotten wrong.

Writing 710 lines of JavaScript also taught me something about scope: the features that took longest weren't the flashy ones (search, filters) — it was the edge cases. What happens when someone adds 0 of something? What if the form submits twice? The invisible 20% of the work.
